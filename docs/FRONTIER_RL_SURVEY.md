# GRPO 前沿方法调研（2026-10-22）

本页回答一个问题：针对 GRPO-v3 / GRPO-v3-all 暴露出的 8 个问题（`docs/GRPO_V3.md`，以及用户 2026-10-22 的观察表），2025–2026 年的前沿后训练方法里，哪些值得在这个项目上试，哪些不值得，为什么。起因是 NVIDIA 工程师建议"试最前沿的方法"。

**调研方式。** 8 个方向并行检索（动态选题、一致性/反事实奖励、特权教师自蒸馏、优化目标与稳定性、评估与选点、NVIDIA 专项、2026 新方法扫描、公平性专项），共 96 条、去重后 89 个方法。每个方法再由两个独立 agent 核实：一个核对来源是否存在、机制与数字是否与论文一致；一个站在质疑方立场判断"在本项目的二元判决、无思维链、16 rollout、LoRA、45 GPU-h 预算下是否真有用"，并给出最小可预注册实验。截至本稿：138/147 个方法两路核实完成（有用：可能 56 / 否 82 / 是 0），9 个只有一路核实（附表标"未核实"）。来源核实用的是 arXiv / 博客 / GitHub 页面直接抓取，页面上的数字都对过；未能确认的标为"部分准确"。中间文件在 `/ritom/scratch/cscs/zhang/xw/tmp/survey/`。

## 一句话结论

多数"前沿 RL 算法"在这个任务上是空操作或方向相反（原因见下一节）。真正对得上病因、且质疑方也没驳倒的，是三族：

1. **以"模型自己的无属性判决"为目标的一致性 / 特权教师自蒸馏**（BCT、OPCD、SDFT/SDPO、OPSD、SelfCI、REM、Co-rewarding）。这是 2026 年各大实验室后训练的共同走向（DeepSeek-V4、Qwen3.5-Omni、Nemotron 3 Ultra 都是"分领域 RL → on-policy 蒸馏合并"），也是用户"一致性奖励"提案的稠密形式。
2. **零训练成本的评估与选点方法**（配对聚类 CI + 最小可检测效应、teacher-forced p(hire) 监控、预注册选点规则、尾部 checkpoint 平均）。它们直接处理观察 6、7，而观察 7 很可能根本不是训练问题。
3. **动态选题的两个便宜门控实验**（重新 profile，检验观察 3 是"过时"还是"选择偏差"；用 prompt replay 做 DAPO 的补充策略）。

要记住的基线：DPO_V3_4880 已按标准优于 SFT-v3（−1.03 pp [−1.81, −0.28]，四项护栏全过，`docs/V3_NEW_DATA.md`）。任何 GRPO 族的新臂，要有意义就得在匹配录用率下赢过这个数并过护栏；否则"前沿"只是换了个名字的 −0.5 pp。

## 为什么多数前沿方法在这里不起作用：六个结构性事实

| 事实 | 证据 | 被它排除的方法 |
|---|---|---|
| 策略比率恒为 1 | 每个 rollout 只做一次优化步（num_iterations=1）；job 5116822 全程 clip_ratio 0.000 | 所有重要性比率 / 裁剪类变体：GSPO、CISPO、SAPO、VESPO、LUSPO、GMPO、INTELLECT-2 双侧裁剪、clip-higher。它们在该配置下和 REINFORCE 逐字相同；只有 DAPO 的"每 rollout 两步"才让它们生效 |
| 审计是贪心解码，判决是一个 token | `docs/EVAL_STANDARD.md`：不稳定集 = 贪心判决在属性值间翻转；翻转只发生在无属性 margin 接近 0 的边界 CV 上 | 从"16 个全同的组"里榨信号的方法：BroRL 扩采到 512、先扩采到 64/128 再筛、RL-ZVP 熵整形、Knapsack 预算分配。P(混合)=1−p^N−(1−p)^N 说明"全同"多半是欠采样，但 1/64 的异议对应约 4 nats 的 margin，属性注入推不动它 |
| 熵在 feedback 文本上，不在判决上 | 日志 token 级平均熵全程 0.42–0.44，没有坍缩；判决只有 1 个 token，其余约 38 个 token 共享同一 advantage | 熵奖励、自适应熵（Skywork-OR1）、Clip-Cov / KL-Cov、top_entropy_quantile（在这种格式上机制反转：高熵 token 是 feedback 用词） |
| TPR 失败是锚的系统偏移，不是噪声 | 锚 prompt 在 450 个无属性基准 CV 上拒绝 79.1%（单次）/ 78.0%（贪心），GPT-4o 拒绝 66.7%（`docs/SFT_V3_ANCHORS.md`，job 5071748）；训练中锚一致率 0.67→0.88，GPT-4o 录用处的录用率 57.7%→47.6% | 噪声校正（Noise-corrected GRPO、Cai et al.）、软目标（对投票比例的 Brier）、拉格朗日约束（Constrained GRPO：约束量在训练行上从未被违反）、KL 重置 / mixup（ProRL、TR-DPO：KL 到 SFT-v3 是唯一拉住录用率的项，重置只会放开它）。模型学得越像锚，TPR 掉得越多 |
| 一致性奖励在 tipped 行上与现奖励逐字节相同 | tipped 的定义是 SFT-v3 无属性多数票与锚一致（free_right_rate > 0.5，`generation/onpolicy.py`）；5,062 个 tipped 行上"与自己无属性判决一致"等于"与锚一致"，只有 4,078 个非 tipped 行不同 | 它改的是观察 4/5 的目标，不解决观察 2（信号用完）。目标取自当前策略会自我锐化；取自冻结 SFT-v3 则会复制 SFT-v3 自己在边界 CV 上会翻的分布 |
| 观察 7 是分辨率问题 | 525 与 571 只差 6/450 个无属性判决；两个 Δ（−1.02 / −0.56）之差约 12/2,700 个集，而 95% CI 半宽约 1 pp；TPR −10.11 对限值 −10 | lr 衰减、EMA、checkpoint 平均、第二个 seed 治的都是别的噪声源。两个数压在阈值边上，先算配对聚类 SE 和最小可检测效应（MDE） |

另一个待检验的假设：**观察 3 可能是选择偏差而非过时**。p 来自用来挑行的同一批样本（赢者诅咒），所以"预测 87% 分裂"本身就偏高。门控实验 1.5 GPU-h：用 SFT-v3 在 9,140 个 prompt 上重新 k=16 采样。若预测分裂率 ≤60%（接近实测 52%），是选择偏差，"按当前策略动态挑题"的过时论据不成立；若 ≥80%，才是过时。

## 三族里的具体候选

### A. 一致性 / 特权教师自蒸馏（目标 = 自己的无属性判决）

共同点：把每对里存着的无属性 prompt（pool 的 `prompts.parquet`，kind='attr_free'，按 pair_id 关联）当特权上下文，教师和学生是同一权重。差别在：目标是采样 token 的 log-prob 差（OPD）还是全词表 KL（OPCD / OPSD）；教师冻结（SFT-v3，adapter 关掉）还是 EMA / 活的；KL 的方向。

| 方法 | 机制一句话 | 对本项目的要点 | 质疑方 |
|---|---|---|---|
| **OPCD**（Microsoft，2602.12275，2026-02） | 学生无上下文采样，冻结教师带上下文，学生 top-k 上的反向 KL | 论文发现冻结教师优于"自己做教师"（Sokoban 53.9 vs 18.8）；安全分类任务上 on-policy 胜 off-policy 上下文蒸馏（后者就是在无属性输出上做 SFT）。只蒸判决 token 的版本 3–4 GPU-h | 固定点是 SFT-v3 在无属性 CV 上的软判决，不锐化；不稳定集几乎都在 SFT-v3 自己边界的对上 |
| **SDFT / SDPO**（MIT / ETH，2601.19897 ICML 2026 spotlight；2601.20802） | SDFT：教师 = 同网络 + 特权示例，EMA 权重，全词表 KL；SDPO：(1−w)·策略损失 + w·蒸馏，教师看 prompt + 成功的同组样本 / 反馈 | TRL 1.15 已装 `trl.experimental.sdft` / `sdpo`（teacher_model_kind ∈ {base, ema, live}，distillation_mode ∈ {sampled_token, topk_logits, full_logits}，distillation_weight），另有 distillation、iw_opd、async_distillation。但它们继承 _BaseTrainer 而非 GRPOTrainer：本项目的权重同步、合并保留检查、判决监控要移植成回调；教师 prompt 模板得"替换"学生 prompt 而非追加 | "token 上稠密 ≠ 信息上稠密"：论文的教师看的是解或反馈，这里教师看的信息比学生少 |
| **Thinking Machines OPD**（博客 2025-10） | advantage_t = −(log π_S − log π_T) 逐 token，折扣 0，直接复用 RL 的 IS 损失 | 在现有 GRPOTrainer 子类里加一次 no-grad 前向（[x_free; y]，adapter 关闭）即可，+15–25% 步时 | 与 DAPO 冲突：DAPO 丢掉的全同组正是它声称起作用的地方 |
| **OPSD**（UCLA / Meta，2601.18734，2026-01） | 教师固定在初始策略 + 特权信息，前向 KL 全词表，G=1 | 8–12 GPU-h/epoch | 同上贪心审计论证 |
| **SelfCI**（KAIST，2605.20258，2026-05） | 目标就是"加入不允许的信息后下一 token 分布不变"；发现单纯"去信息"教师欠定，用去信息教师 × 任务教师的乘积 | 与本项目问题形式最接近（LoRA r32、7–8B、GRPO 标量奖励作基线）；两次教师前向，32–36 GPU-h | 同上 |
| **门控（先做）**：Zou et al. 2610.22512（2026-10-15） | 训练前算采样 token 反向 KL 与"错步 KL 对比"，预测特权信息是否有用 | 1–2 GPU-h：在 SFT-v3 和 ckpt 525 / 571 上算判决 token 的 KL(attr‖free)。若全同组上的中位 KL 很小，这一族没有信号，整族不跑 | tipped 的定义已是这个 KL 的采样估计，门控有循环论证之嫌 |

| 配对 / 一致性奖励 | 机制 | 要点 | 质疑方 |
|---|---|---|---|
| **BCT**（DeepMind，2510.27062，2025-10） | 当前模型在干净 prompt 上生成目标，带 cue 的 prompt 上做纯 SFT | 最便宜（5–7 GPU-h），录用率天然钉在自己无属性录用率上。目标直接用 pool 里已存的 SFT-v3 无属性 8 票多数 | RFT 对照（job 5066776，+0.31 pp）就是它的"锚目标"版，为零；所以这是"对比 vs 模仿"的决定性实验，不是新方法 |
| **Cross-prompt 一致性奖励**（Co-rewarding，ICLR 2026） | 用另一视图的多数票给本视图打分，避免单视图自我一致的坍缩（单视图多数票的伪标签准确率会掉到 ~0） | 用户观察 4 提案的具体化；TRL 奖励函数能读数据列，加 neutral_decision 列即可 | tipped 行上与现奖励完全相同；只在 4,078 非 tipped 行上不同，而且目标是噪声更大的自我目标 |
| **REM**（Meta，2610.22942，2026-10-16） | 两臂各自 GRPO 组，再加 −α(μ−μ′)(r_i−r̄_{−i}) 修正项匹配期望奖励 | 最接近的已发表类比；录用指示的 gap 正是观察 6 要监控的量 | 0/1 判决下全同组上修正项恒为 0；对确定性翻转（中性全 hire、带属性全 reject）梯度为零 |
| **Debiasing-DPO**（Stanford，2604.02585，COLM 2026） | chosen = 自己在无 spurious 上下文下的回答，rejected = 带上下文的回答，加 SFT 锚 | 本仓库的 DPO 配方已是这个结构（loss_type [sigmoid, sft] 1.0 / 0.2）；唯一没试的变化：chosen 的判决取自己的无属性判决而非锚。DPO_V3_4880 是现在最好的臂，这是在赢家上做的约 5 GPU-h 变体 | 与 DPO_V3_4880 重复，"新"只在目标 |
| PA-GRPO（ACL 2026，2603.21016）：可能；EIS-GRPO / J4R（Salesforce，2505.13346）：否；J1（Meta，2505.10320）：否；BCT-Chua（2403.05518）：可能；因果一致性 DPO（Hüyük，ICLR 2025，2410.03767）：可能 | 把同一条目的所有反事实变体放进一个 advantage 组 / 两个顺序都对才给奖励 | 结构上与"组内反事实集"完全对应；需要子类改 advantage 分组 | PA-GRPO 的模态一致性奖励（±1）会压过 0/+1 的锚奖励，在 hire 锚但策略偏 reject 的 CV 上把它推向 reject；EIS 的新信号（子组全同而兄弟变体分裂）在本数据上几乎为空；J1 的 AND 奖励只改 prompt 权重不改学到的东西；一致性 DPO 的重标在现有 DPO 对上是空操作（对只建在 tipped 行上） |

### B. 评估、选点、监控（0 训练成本）

| 方法 | 做什么 | 要点 |
|---|---|---|
| 配对聚类 CI + MDE（Miller 2024，2411.00640） | 每个集的配对差，按候选人聚类；训练前算最小可检测效应 | `scripts/operating_point_control.py` 的 matched_comparison 已经是配对聚类 bootstrap；缺的是报告 SE / MDE80 / MDE90、设计效应，以及在每次 bootstrap 里重估匹配切点。0 GPU-h。结果写进 EVAL_STANDARD |
| teacher-forced p(hire) 监控 | 固定前缀 `{"decision": "` 后读 P(hire)/(P(hire)+P(reject))，一次前向 | 替换"投影录用率"带（23.5% vs 实际 19.09%）。回溯 GRPO-v3-all 的 20 个 checkpoint 验证它能否预测审计结果。期望翻转率要按贪心定义（看 margin 符号），不是独立抽样 |

| lr cooldown | transformers 5.17 有 warmup_stable_decay / cosine_with_min_lr 开关 | 先做 Tier 0：525 vs 571 的 Δ 的 CI 若含 0，观察 7 就是报告问题不是调度问题 |

### C. 动态选题（观察 2、3）：DAPO 之外的补充

- **Nemotron 3 Nano 配方**（2512.20848）：SFT checkpoint profile → 丢 pass-rate 1.0 → 按 pass rate 的高斯课程 → 平台期用最好的 RL checkpoint 重 profile。前三步 `build_grpo_prompts.py` 已做；新的是"重 profile"。Stage 0 就是上面的观察 3 门控。
- **Prompt Replay**（2603.21177）：把最近分裂过的 prompt 放进优先队列，替代 DAPO 的 RefillOrder 随机排列；对 DAPO 的"fill < 0.5 就停"是直接补救。注意：训到后期仍分裂的 prompt 多半是锚本身接近平票的（8 票里 ≤6），要只收 margin ≥ 7/8 的。
- **精确 logit 选题**（PCL 的价值模型换成判决 token 概率）：无思维链下 p_θ(anchor | prompt, 前缀) 就是精确的期望奖励，比 16 次伯努利抽样方差低得多；用 vLLM max_tokens=1 扫全池。但"p≈0.5"分不清 tipped 行（p_free≈1）和边界 CV（p_free≈0.5），要和 attr_free 的 p 一起读。
- **类平衡动态采样**（BD-GRPO，2605.29076，已核实：否，机制对应的是类不平衡数据集，这里两侧各半且 DAPO 已做平衡）：最接近的已发表类比，小 Qwen3 做文本分类的 GRPO。它发现不按类平衡的零方差过滤会坍缩到多数类，正是这里的"掉向 reject"。支持 DAPO 的严格平衡决定。
- **NVIDIA 的反面证据**：AceReason-Nemotron 与 Nemotron-Cascade（2512.13607）都发现"每 rollout 多步 + clip-higher"在 100–150 步内熵坍缩，严格单步 on-policy 更稳。DAPO-v3 用的是两步 + 0.28。可预注册的预测：DAPO 的 dapo/probe_zero_variance 在同样 prompt 消耗量下比 GRPO-v3-all 高 ≥10 pp 即为坍缩加速。
- **scale_rewards='none' / Dr. GRPO**（Bereket & Leskovec，2508.11800）：组内 std 归一化让 15/1 组里的独苗拿到 |A|≈3.9，后 100 步的方向由一两个独苗决定。一个开关，但会改变 hire / reject 两侧的权重（Σk(16−k) vs Σ√(k(16−k))）。

### D. NVIDIA 专项：哪些对得上

| NVIDIA 方法 | 结论 |
|---|---|
| ProRL / ProRL v2（2505.24864；2507.12507）：KL 信赖域 + 周期性参考重置 | 否。这里 KL 没有"主导并冻结学习"（k3 KL 全程 0.016–0.035 nats/token），而 KL 到 SFT-v3 是唯一拉住录用率的项，重置只会放开 TPR |
| BroRL（2510.01180，ICML 2026）：每题 512 个 rollout | 否。机制是大输出空间里的覆盖；这里奖励只在一个二元 token 上，贪心审计看不到 1/64 的异议。门控 0.3–0.5 GPU-h 可以确认 |
| GDPO（2601.05242）：多奖励解耦归一化 | 否（确认观察 8）。TRL 1.15 已有 multi_objective_aggregation='normalize_then_sum'；等有第二个非常数奖励再说 |
| DLER：批级奖励归一化 + 动态采样 + clip-higher + 长度惩罚 | 长度惩罚无关；批级归一化 = scale_rewards='batch' 一个开关；其余 DAPO 已含 |
| RLBFF（2509.21319，ICLR 2026）/ GenRM：对 feedback 字段用原则奖励 | 否。词法检测器在 31,050 条审计里几乎不触发，feedback 不提属性；且违反"奖励里不放模型"的设计 |
| QeRL（2510.11696）：量化噪声当探索 | 否。饱和不是探索不足 |
| RLP（2510.01265，ICLR 2026） | 无关（无预训练阶段、无思维链） |
| Nemotron 3 Nano / Super / Ultra 配方：profile、多环境同训、GenRM | 多环境同训防的是跨领域遗忘，TPR 失败不是遗忘；profile / 重 profile 见 C |
| NeMo-RL（v0.4–0.7）的 IS 校正（TIS / ICE-POP / seq-mask-tis） | TRL 1.15 已有同类开关且默认开；实测 vLLM 与训练器 log-prob 差 0.012 nats/token，比率 0.999，无需处理 |
| **NVIDIA 自己的方向**：NeMo-RL v0.7 为 Nemotron 3 Ultra 加了 multi-teacher on-policy distillation（MOPD） | 与 A 族一致：NVIDIA 内部也在往 on-policy 蒸馏走 |

### E. 2026 模型报告的后训练套路

Qwen3.5（本项目的底座）没有独立技术报告；Qwen 系在 2026 的公开配方是 GSPO（= TRL importance_sampling_level='sequence'）训分领域专家，再 on-policy 蒸馏合并（Qwen3.5-Omni，2604.15804）。DeepSeek-V4（2606.19348）：GRPO 专家 → 反向 KL on-policy 蒸馏合并，取代混合 RL 阶段。GLM-5 的 IcePop 掩码（已核实为失配校正，这里失配约 0）。共同点是"RL 出方向，蒸馏定幅度"。对本项目的类比（已核实：否）：把晚期 checkpoint 混合当教师做 OPD，对一个二元 token 来说反向 KL 的最优解就是混合本身，学生只会收敛到那个概率，不会更稳。
